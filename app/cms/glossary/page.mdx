# Glossary

Terms used across the CMS documentation, each with one meaning. Where a term is a control on screen, the label is quoted as it is rendered.

| Term | Meaning |
| --- | --- |
| **Organization** | A clinic's account: its staff, locations, and patients. The screen spells it **Organisation**. A person's role is set per organization. |
| **Clinic location** | One physical site of an organization. Sessions, rooms, and the queue are scoped to one location at a time. |
| **Member** | A person's place in one organization, with one role there. |
| **Role** | Clinic Admin, Receptionist, Doctor, or Nurse, held per organization. See [Roles & Permissions](/cms/roles-and-permissions). |
| **Session** | A clinic location's working day: which staff are on duty and which rooms are open. Opened from [Session Setup](/cms/session-setup). |
| **Shift** | One rostered block of work for one staff member. See [Rostering](/cms/rostering). |
| **Queue ticket** | The number a checked-in patient is called by. See [Reception Queue](/cms/reception-queue). |
| **Stage** | Where a checked-in patient is in the visit: Nurse, Doctor, Investigations, Dispensary, or Completed. |
| **Appointment** | A booked time slot for a patient. |
| **Booking request** | A patient's request from the portal that is not yet an appointment. |
| **Encounter** | The clinical record of one visit, started from the chart or the queue. See [Encounters & Clinical Notes](/cms/encounters). |
| **Chart** | Everything the CMS shows for one patient, split into sections. See [Patient Records & Consent](/cms/patient-records). |
| **Void** | Mark a record as made in error while keeping it for the history. Different from deleting it. |
| **Publish (roster)** | Make a draft week of shifts official. Only a Clinic Admin can publish. |
| **Finalize (attendance)** | Lock a day's attendance records. See [Attendance](/cms/attendance). |
| **Order set** | A saved group of orders a clinician can apply to an encounter at once. See [Orders & Order Sets](/cms/orders-and-order-sets). |
| **Formulary** | The clinic's list of medications it can prescribe. See [Formulary](/cms/formulary). |
| **Lot** | A batch of stock received into inventory, with its own quantity and expiry. See [Inventory & Stock](/cms/inventory-and-stock). |
| **Ping** | A short task or message sent to a staff member. See [Tasks & Staff Pings](/cms/tasks). |
| **Patient portal** | A separate, patient-facing app where a clinic's patients manage their care. See [Patient Portal](/cms/patient-portal). |
| **MCR, SNB** | Registration numbers for doctors (Medical Council) and nurses (Nursing Board), entered on the staff form. |
| **Caregiver** | A family member or carer who uses the patient portal for a patient with their own account, read-only or able to make changes. See [Caregiver access](/cms/patient-portal#caregiver-access). |
| **SmartCMS** | Synapxe's gateway to Singapore's national health systems. See [SmartCMS](/cms/smartcms). |
| **HE code** | A clinic location's MOH Health Establishment code, which SmartCMS identifies it by. See [Singapore Registration](/cms/smartcms/registration). |
| **CHAS** | The Community Health Assist Scheme. Medbot verifies a patient's CHAS card at check-in and claims CHAS subsidies from the bill. See [Claims Workflow](/cms/smartcms/claims). |
| **Medisave (CDMP)** | Paying part of a chronic disease bill from a patient's or family member's Medisave account, claimed from CPF. See [Claims Workflow](/cms/smartcms/claims#medisave). |
| **ICD-10-AM** | The diagnosis coding MOH requires on claims and reports. Coded on the visit's **Diagnoses (ICD-10-AM)** card. |
| **Claims queue** | Every SmartCMS claim the organisation has prepared, with its status. At **SmartCMS → Claims**. |
| **Claims agent** | The automated run, or AI agent, that prepares claims and reports under the organisation's agent policy. See [Claims Agent](/cms/smartcms/claims-agent). |
| **Entitlement** | Synapxe's approval for one clinic location to use one SmartCMS service. Recorded on [SmartCMS Settings](/cms/smartcms/settings). |
