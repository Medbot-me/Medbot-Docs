# SmartCMS Settings

The **SmartCMS** settings page is where an organisation's admin switches each clinic location on for each SmartCMS service, checks the connection and accreditation, sets the agent policy, and prepares the paperwork Synapxe asks for.

Open it from [Organisation Settings](/cms/settings#integrations): in the **Singapore integrations** card, select **SmartCMS settings**. The page is at `/organisations/[id]/smartcms`. Only an **admin** of a Singapore organisation can open it.

The page's header says which Synapxe environment this Medbot server talks to:

- "This server connects to Synapxe UAT. A location sends only in the environment it is approved for." (or "production")
- If SmartCMS is switched off on the server: "SmartCMS is not enabled on this server; settings are saved but nothing is sent."
- On Medbot's simulated clinic, which gateway the running server actually talks to: the SmartCMS mock ("This server connects to the SmartCMS mock …, not to Synapxe."), a local UAT stand-in, or Synapxe UAT. In UAT mode it adds "Only what a person clicks is sent." See [The simulated clinic and UAT mode](#the-simulated-clinic-and-uat-mode).

From top to bottom, the page has these cards.

## Agent policy

How far an AI agent may take a claim: **Off: agents never prepare claims**, **Prepare only: a person submits**, or **Auto-submit routine claims**. Select **Save policy**. **Auto-submit** appears only once a location is approved for production for CHAS, Medisave or Screen for Life claims, and Medbot refuses to save it before then. At a location or for a module not in production, a saved **Auto-submit** acts as **Prepare only**. See [Claims Agent](/cms/smartcms/claims-agent#agent-policy).

## Agent credentials

Tokens an AI assistant uses to reach Medbot's SmartCMS claims tools, for one location or the whole organisation, lasting up to 30 days. A token is shown once, at creation. See [Claims Agent](/cms/smartcms/claims-agent#create-an-agent-credential).

## Referral contribution to NEHR

Shown when the organisation subscribes to **Referral contribution to NEHR**. The card says "Issued referral letters go to NEHR without review, unless they may mention termination of pregnancy, sterilisation or organ transplant: those wait for a doctor’s consent check. Each location sends a reconciliation file every night at 00:15." It also gives **Who sees and resends** (**Doctors and admins**), **Who confirms consent** (**Doctors only**) and **During a SmartCMS outage** (**Letters wait, then send**), with a link to **Open Reports**.

An active location with no HE code is named: "No HE code at …: referral letters from there are not sent to NEHR." See [NEHR referral letters](/cms/smartcms/reports#nehr-referral-letters).

## Clinic locations

Choose a location from the location list. Each location shows its HE code and Hospital Code (with **Edit codes**), then one row per subscribed module.

### Switching a service on at a location

**Entitlement** is Synapxe's approval for one location to use one service. Once Synapxe approves a location, record it here:

1. Find the module's row under the location.
2. Set **Environment** to **Off**, **UAT** or **Production**, to match what Synapxe approved.
3. Enter the **Synapxe reference** (the approval reference Synapxe gave you).
4. For migrant worker health reporting, also enter the **MOM organisation code**.
5. Save the row.

A location sends only when its environment matches the one this server connects to. A location needs an HE code before any service can be switched on, and Medisave also needs a Hospital Code. Every location starts **Off**. Switching a service off parks its unsent claims: nothing is sent and nothing is deleted.

Each location can also set **Agent policy at this location**, or leave it as **Same as the organisation**.

### Changing an HE code

Synapxe knows each location by its HE code. Changing an existing HE code switches every SmartCMS service at that location **off**, so nothing is sent under a code Synapxe has not approved. Changing the Hospital Code switches off only Medisave. You are asked to confirm before saving.

After the change, the location shows a reminder: send Synapxe an **UPDATE** row from **Synapxe onboarding** (below), and switch the services back on once Synapxe approves the new code. Also ask the CIDC administrator to update the HE code in their system. See [Singapore Registration](/cms/smartcms/registration).

### Testing the connection

**Test connection** sends a test enquiry to SmartCMS from that location and shows the result.

### Accreditation

**Check accreditation** asks MHCP whether the location is accredited, for each of the accreditation types Medbot checks: `CM`, `PHPC` and `CD`. Each shows **Accredited**, **Suspended**, **Not accredited**, or the date accreditation starts, with the period, any suspensions, and the HE code it was checked for. A scheme not yet asked about shows **Not checked yet**. If the location's HE code has changed since the check, the panel says so: check again.

A location that is not accredited for a scheme cannot claim under it, so check before you switch it on. If MHCP refuses the check, or answers that the location is not authorised, the panel shows MHCP's code and words and says what to do, and Medbot stops at the first refusal instead of asking about the other types.

**Ask about another clinic.** An admin can ask MHCP about any clinic's accreditation: enter its **HE code**, choose the **Type** (`CM`, `PHPC` or `CD`) and select **Ask**. The enquiry is "Sent as this location. The answer is shown here and is not saved as this location’s accreditation." It is logged and audited like the location's own check. Asking about another clinic's HE code needs Synapxe's agreement, so until this Medbot server allows it the panel says "Synapxe has not agreed to enquiries about other clinics yet" and only the location's own HE code can be asked about.

## Synapxe onboarding

Synapxe onboards clinics from a spreadsheet template. This card exports the organisation's clinic rows in that format, one per location. Choose the action:

- **NEW: onboard these clinics**
- **UPDATE: change clinic details** (for example after an HE code change; the row carries the old and the new code)
- **DELETE: clinic no longer exists**

Select **Download CSV** and send the file to Synapxe. Locations missing an HE code or Hospital Code are listed so you can complete them first.

## SIT evidence

For Synapxe's system integration testing (SIT), the clinic must show evidence of each test scenario. This card is only useful on a server connected to Synapxe **UAT**.

1. Select **Start run** with the scenario's tag, for example `ACC-01-01`.
2. Carry out the scenario in the CMS.
3. Select **End**, then **Download evidence**. The file holds every message Medbot sent to SmartCMS during the run and every reply, up to 500 messages, with each message's `x-amzn-requestid` and `x-amz-apigw-id`.

While a run is open, [SmartCMS Messages](/cms/smartcms/messages) can be filtered to it and updates itself every few seconds, so you can watch each scenario's messages as you go.

Medbot keeps an encrypted record of every SmartCMS message and reply for audit, whether or not a SIT run is open.

## The simulated clinic and UAT mode

Medbot tests SmartCMS against Synapxe's UAT gateway from a **simulated clinic**: a stack with synthetic patients and staff, and a UAT test clinic with Synapxe's own test identity. It is not a customer clinic. Its strip at the top of every page reads "SIMULATED CLINIC: synthetic patients and staff on a local stack." followed by the gateway the server talks to, for example **SmartCMS: UAT (cag-uat), clicks only**, or **SmartCMS: mock (…)**. A real gateway is marked out in white, so a screenshot from UAT cannot be mistaken for mock evidence. If the server does not answer, the strip says **SmartCMS: gateway unknown**.

In UAT mode, two guards decide what may be sent:

- **Clicks only.** Only what a person clicks is sent. Scheduled jobs, the outage probe and check-in's automatic CHAS verification send nothing, and a failed send is not retried by itself: the claim offers **Send again** instead. **Submit all prepared** is not offered.
- **Test patients only.** A request that carries any NRIC or FIN other than Synapxe's test patients is refused before it is sent. A check refused this way shows **Not checked in UAT mode**, and a claim is held with the reason. The test patients are Synapxe's sample patient and the ten CDMP test patients Synapxe allotted to Medbot for the November 2026 CDMP tests.

These guards never apply to a production server.

The UAT test clinic has the ten CDMP test patients registered, with no visit, bill or claim, so a tester makes those in the CMS during a SIT run. CDMP visits are seen by a separate doctor, "Clara Doctor (UAT CDMP)", whose MCR is on Synapxe's list for the CDMP tests. The clinic's other doctor stays the attending doctor for the other services.
