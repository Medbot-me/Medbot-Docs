# SmartCMS (Singapore)

**SmartCMS** is the national gateway, run by **Synapxe**, that Singapore clinic management systems call to reach MOH and agency back-ends: CHAS and MOH subsidy claims, Medisave (CDMP) claims, Screen for Life, the National Immunisation Registry, disease notification, chronic disease indicators, NEHR referrals, migrant worker health reporting and more.

Medbot CMS runs these national workflows from the screens a clinic already uses. Staff verify a patient's CHAS card at check-in, code diagnoses during the consultation, and choose claims when they bill the visit. Medbot then prepares, sends and tracks the claims and reports.

> **Status: built, awaiting Synapxe certification.** The claims and reports workflows on these pages are built to Synapxe's specifications and tested against a mock gateway. Nothing is sent for a clinic location until Synapxe approves it and an admin switches it on in [SmartCMS Settings](/cms/smartcms/settings). See [What works today](#what-works-today).

## How it fits together

Two layers sit between Medbot and the national back-ends:

| Layer | What it does |
| --- | --- |
| **CAG** (the API gateway) | Authenticates the caller with an API key and a short-lived signed JWT. |
| **SCG** (the SmartCMS Gateway) | Checks the message envelope, routes it to the right back-end, and checks that the clinic is entitled to that service. |

Every call names the clinic by its **MOH HE code**, so each clinic location needs one before it can connect.

SmartCMS is enabled **per organisation** and only for organisations whose country is **Singapore (`SG`)**. Everywhere else, none of it appears.

## Key concepts

| Concept | What it is |
| --- | --- |
| **Module** | A group of SmartCMS services a clinic subscribes to, e.g. "CHAS and MOH subsidy claims" or "National Immunisation Registry". An admin chooses them when [creating the organisation](/cms/create-organisation) or later in [Organisation Settings](/cms/settings#integrations). See [Modules & Gating](/cms/smartcms/modules). |
| **Badge** | Synapxe's grouping of modules for certification: **CHAS Badge**, **Migrant Worker Health Badge**, **Healthier SG bundle**. |
| **HE code** | The MOH Health Establishment code of one clinic location. SmartCMS identifies the clinic on every call by this code. See [Singapore Registration](/cms/smartcms/registration). |
| **Regulatory identity** | The organisation's UEN and GST details, each location's HE code and Hospital Code, and each practitioner's MCR or SNB number. |
| **Entitlement** | Synapxe's approval for **one location** to use **one service group** in **one environment** (UAT or production). An admin records it in [SmartCMS Settings](/cms/smartcms/settings). Nothing is sent for a location that is not switched on. |
| **Claims queue** | Every claim the organisation has prepared, with its status at MHCP or CPF. See [Claims Workflow](/cms/smartcms/claims). |
| **Claims today** | One clinic day's patients, with each bill, its claims and what the patient still owes. See [Claims today](/cms/smartcms/claims#claims-today). |
| **Agent policy** | How far an AI agent may take a claim: off, prepare only, or auto-submit. See [Claims Agent](/cms/smartcms/claims-agent). |
| **Evidence log** | An encrypted record of every message Medbot sends to SmartCMS and every reply, kept for audit and certification. |

## What works today

| Area | State |
| --- | --- |
| Choosing SmartCMS modules (wizard and settings) | Available |
| **Singapore registration**: UEN, GST, HE code, Hospital Code, location email and phone | Available |
| **SmartCMS settings**: switching services on per location, connection test, accreditation check, agent policy, agent credentials, Synapxe onboarding export, SIT evidence | Available |
| **CHAS verification** at check-in and **Verify now** | Available |
| **Coded diagnoses** (ICD-10-AM) on the visit | Available |
| **Singapore billing**: one bill per visit, receipt numbers, GST, bill categories, void and correct | Available |
| **Claims**: CHAS, PHPC, vaccination and CDS subsidies, Screen for Life, Medisave | Available |
| **Claims queue**: submit, re-prepare, discard, status tracking, CHAS appeals, resubmitting rejected claims, Medisave amend and cancel, CPF payment reconciliation, matching CPF messages, the 30-day CPF answer check | Available |
| **Claims today**: each patient's bill, claims and what they owe, by location and day | Available |
| **Claims agent**: nightly run, "Prepare today's claims", AI assistant connections over MCP | Available |
| **Reports**: NIR, disease notification (DEROM), CIDC, NEHR referral letters, migrant worker health | Available |
| Sending to Synapxe UAT or production | Waiting on Synapxe's approval of each location |
| Medical alerts and allergies (CMIS), Healthier SG | Planned |

## The screens

A Singapore organisation with a matching module gets a **SmartCMS** group in the sidebar:

| Screen | What it is for |
| --- | --- |
| **Claims** (`/claims`) | The claims queue, **Claims today**, the claims agent, notes for staff, and Medisave payments. See [Claims Workflow](/cms/smartcms/claims). |
| **Reports** (`/reports`) | National registry notifications and reports. See [Reports](/cms/smartcms/reports). |

SmartCMS also adds to screens staff already use:

| Screen | What SmartCMS adds |
| --- | --- |
| [Reception Queue](/cms/reception-queue) and the patient header | CHAS verification and the CHAS badge |
| [Encounters](/cms/encounters) | The **Diagnoses (ICD-10-AM)** card, Screen for Life and developmental screening panels |
| [Vaccinations](/cms/vaccinations) | The SDD product and the vaccination subsidy check |
| [Billing](/cms/billing) | The claim panels on **Generate invoice**, and void and correct |
| [Organisation Settings](/cms/settings) | Modules, Singapore registration, and the link to **SmartCMS settings** |
