# Getting Started

Medbot CMS needs three external services configured before it will run: [Medplum](https://www.medplum.com) for clinical data, [Clerk](https://clerk.com) for staff authentication, and a Postgres database for local operational state.

## 1. Create a Medplum account

Each clinic (organisation) uses its own Medplum project, and its credentials are entered in the app, not in environment variables. The CMS itself holds no Medplum credentials.

1. Sign up for a free account at [app.medplum.com/signin](https://app.medplum.com/signin).
2. Create an OAuth client in Medplum.
3. Keep its **Client ID** and **Client Secret** for step 6, when you [create the organisation](/cms/create-organisation).

No Medplum project? Ask Medbot to host one: see [Medbot-Hosted Organisations](/cms/hosted-organisations).

## 2. Configure Clerk authentication

From your Clerk dashboard, obtain the **Publishable Key**, **Secret Key**, and set:

```bash
NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY=your_publishable_key
CLERK_SECRET_KEY=your_secret_key
```

`CLERK_WEBHOOK_SIGNING_SECRET` is generated only after you create a webhook endpoint — see [Configure the Clerk webhook](#configure-the-clerk-webhook) below, then add:

```bash
CLERK_WEBHOOK_SIGNING_SECRET=your_webhook_signing_secret
```

## 3. Configure the database

Use either a Neon Postgres database or a local Postgres instance:

```bash
DATABASE_URL=your_database_url
```

## 4. Sync the database schema

```bash
pnpm drizzle-kit push
```

This applies the Drizzle schema to Postgres. Postgres holds only the operational state Medplum doesn't model — clinic locations, rooms, sessions, the queue, roster and attendance, and similar day-to-day scheduling detail; Medplum stays the source of truth for patients, practitioners, appointments, and clinical data. Run `drizzle-kit push` again after pulling any schema change. A few features ship their own SQL migration notes under `src/db/migration-notes/` for databases where a live `db:push` isn't appropriate (results-review duties, vaccination stock operations, order sets, and the multi-location queue backfill) — apply those directly when needed.

## 5. Run the application

```bash
pnpm run dev
```

## 6. Create your organisation

There is no manual admin bootstrap. Sign in, then [create an organisation](/cms/create-organisation) with your Medplum client ID and secret: you become its first `admin`. From there, add staff one at a time from `/staff` or in bulk from a [CSV file](/cms/seed-data). See [Roles & Access](/cms/roles-and-permissions) for what each role can do.

## Configure the Clerk webhook

The Clerk webhook synchronizes newly created users after they accept an invitation and sign in.

1. Install LocalTunnel: `npm install -g localtunnel`
2. Expose your local dev server in a new terminal: `lt --port 3000` (adjust the port if different)
3. In the Clerk dashboard, create a webhook endpoint at `https://your-subdomain.loca.lt/api/webhooks/clerk`, subscribed to the `user.created` event.

## Verify setup

- Sign in as the organisation's `admin` and choose the organisation on the [welcome screen](/cms/switching#the-welcome-screen).
- Navigate to [`/staff`](/cms/staff) to register practitioners, `/patients` to register patients.
- Confirm registration records optional contact details and communication-consent combinations; open the patient chart to update either as admin, doctor, and nurse (billing panels stay unavailable to doctor/nurse).
- Navigate to `/appointments`: view, book, edit, and cancel a booking; confirm a closed appointment can't be edited or cancelled.
- Navigate to `/session`: select a location, mark today's active staff, and configure rooms and display devices.
- Navigate to `/queue`: check in a booked appointment and confirm the patient gets a queue ticket, rotates across active session doctors, can be called to a room, and orders by arrival time.
- Open a generated `/display/{token}` URL and confirm the public board shows only queue tickets and room names, never patient identifiers.
- As admin, add an RxNorm medication at `/formulary`, then search, edit, retire, reactivate, and delete it; sign in as doctor or nurse to confirm read-only access.
- As doctor or nurse, record vitals on a patient with a capturable encounter — blood pressure site/position, automatic BMI, abnormal/fever-adjusted indicators, trends, and correction history — then confirm a receptionist can view but not record or correct vitals.
- On the same patient, record a vaccination with both a cataloged CVX vaccine and the free-text "Other" option, then edit and void it; confirm a receptionist has view-only access.

For local demo data, seed patient-facing display devices (after creating at least one active location and room):

```bash
SEED_ALLOW=1 pnpm exec tsx tooling/seed-display-devices.ts
```

The script prints the target database host before writing, creates a Lobby TV and one room-door display for the default location, and prints raw tokens only for newly created devices — re-running it reuses existing devices by name and cannot recover old raw tokens.
