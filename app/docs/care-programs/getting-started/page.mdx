# Creating a Program

## 1. Start a new program

From **Programs → All Programs** (`/programs`), click **New Program**. You'll be asked for:

- **Name** — required, e.g. "Colorectal SOC — Referral to Discharge".
- **Specialty** — optional, e.g. "Colorectal Surgery".
- **Setting** — optional, e.g. "SOC, inpatient, primary care".

Click **Create Program**. The program is created with status `draft` and you're taken straight into the guided setup wizard.

## 2. Walk through the setup wizard

The wizard at `/programs/[programId]/setup` has six steps, shown as a row of numbered pills you can jump between freely — every step is optional and has a sensible default, so nothing here blocks you from finishing early. You can also click **Skip setup for now** at any point and come back later from the program page.

### Step 1 — Roles

A set of default roles is already seeded for you: **Consultant, Clinic nurse, PSA, Dietitian, Care coordinator, Pharmacist**. Rename or remove any of them, or add your own. Only the program's owner can manage roles, here or later from the program page's Care team tab.

### Step 2 — Care team

Add the people covering each role on this program (name, email, care role). You can skip this and add your care team anytime — see [Care Team](/docs/care-programs/care-team).

### Step 3 — Patients

Add patients to this program's cohort from the shared, platform-wide patient directory. You can skip this and add patients later — see [Patients & Cohort](/docs/care-programs/patients).

### Step 4 — Workflow

Describe, in plain language, how this program's workflow should run: the steps patients and staff go through, who does what and when, and any general principles staff or a program agent should follow. There's no graph or builder here — it's saved as free text and handed to every program agent run as context. Optional; leave it blank for now if you like.

### Step 5 — Agents

Create AI agents scoped to a care role, each with its own tools and instructions. You can skip this and add agents later — see [Program Agents](/docs/care-programs/agents).

### Step 6 — Settings

Two independent things, both off by default:

- **Patient agent** — bind a `Patient`-role agent so patients can chat with it over SMS/WhatsApp. See [Patient Agent](/docs/care-programs/patient-agent) for the full walkthrough.
- **On patient added** — what happens the moment a patient is added to this program's cohort: an optional welcome message (sent via Twilio, SMS or WhatsApp, authored in the Content Library) and, separately, an optional program agent triggered against just that new patient.

Use **← Back** / **Next →** to move between steps. On the last step, click **Finish setup** to publish the program (moves it from `draft` to `published`). Every step remains editable after publishing — nothing here is a one-time, locked-in choice.

## 3. Continue setup later

If you skipped the wizard, the **Programs** list shows a **Continue setup** link next to any of your own draft programs. From the program's own page, a banner also appears while the program is still a draft: "This program is still a draft. Finish the guided setup ... to publish it," with a **Finish setup** button.

## 4. The published program page

Once set up, a program's own page (`/programs/[programId]`) organizes everything into tabs:

- **General** — open Task Inbox items for this program, plus a patient-agent summary card (turns in the last 7 days, pending drafts, open escalations, upcoming appointments) if the patient agent is enabled.
- **Patients** — the cohort roster (same view as the setup wizard's Patients step).
- **Agents** — program agents, their run history, and daily schedules.
- **Workflow** — the workflow text editor.
- **Care team** — participants, coverage/rota, availability, and (owner-only) roles.
- **Settings** — patient agent binding, on-patient-added behavior, and (owner-only) a danger zone to delete the program.

Deleting a program (owner-only, from Settings → Danger zone) permanently removes it along with its care team, roles, agents, cohort membership, encounter notes, and message history. This cannot be undone.
