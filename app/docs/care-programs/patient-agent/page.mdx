# Patient Agent

The patient agent is a patient-facing, asynchronous conversational agent that a patient talks to in their own time, over the channel they already use (SMS or WhatsApp via Twilio). It only ever **replies** to a message the patient sent — it never starts a conversation on its own.

## What it can do

| Capability | What the patient can do | What the agent may do on its own |
| --- | --- | --- |
| **Appointments** | Ask for a new appointment, move an existing one, cancel one, ask when their next one is | Read the patient's own appointments; book or move one directly into an open slot on a care team member's published availability; cancel outright |
| **Health education** | Ask questions about their condition, an upcoming procedure, pre-procedure preparation, or medication they were given | Answer from the program's own clinical resources and the patient's own context only; hand off anything outside that scope |
| **Symptom triage** | Report a new or changed symptom between consults | Classify urgency; on a red flag, immediately redirect to emergency services and escalate to the covering care role |

## Setting it up

### 1. Author the agent

Create a program agent with **care role = Patient** on the [Agents tab](/docs/care-programs/agents#the-patient-care-role) — same create/edit form as any other agent, just scoped to this special role.

### 2. Bind it in Settings

On the program page's **Settings** tab, the **Patient agent** card:

- **Enable switch** — "Let patients chat with this program's patient agent."
- **Patient agent** — a dropdown of this program's active, `Patient`-care-role agents. If none exist yet, it links you back to the Agents tab.
- **Delivery mode**:
  - **Review before sending (recommended)** — every drafted reply waits on the patient's page for a staff member to approve, edit, or discard before it sends.
  - **Send automatically** — replies go straight out. A red-flag emergency reply always sends immediately in either mode.
- **Escalation role** — which staff role gets notified on a red flag, a failed turn, or a hand-off; resolved through Coverage to whoever is actually covering that role right now.
- **Emergency number** — e.g. `995`; substituted into the emergency message below.
- **Emergency message** — a template textarea, seeded with a sensible platform default, that must keep the `{emergencyNumber}` placeholder. Sent immediately and unedited whenever the deterministic red-flag screen fires.
- **Hold routine replies overnight** (quiet hours, optional) — a from/to time and timezone. A routine reply drafted inside this window waits until it closes; an emergency reply is never held.

Click **Save**.

## Safety design

A few things are true regardless of settings, and are not configurable away:

- **Red-flag screening runs before the model does**, on the raw message text — deterministic keyword/pattern matching (chest pain, can't breathe, stroke symptoms, heavy bleeding, anaphylaxis, self-harm/suicidal ideation, and more). A hit sends the fixed emergency message and opens an escalation without ever calling the LLM. False positives are accepted; false negatives are the thing this is built to avoid.
- **It never invents an appointment, clinician name, result, or clinical fact.** Appointments only ever come from the appointment tools; anything the agent doesn't know, it hands off to the care team rather than answering.
- **It never diagnoses, changes a prescription, or interprets an unreleased result.**
- **It discloses that it's an automated assistant**, not a clinician, at the start of every new conversation and on request.
- **Structured yes/no replies to an existing scheduled message still go through the normal automated flow** — the patient agent only picks up free text and anything not already correlated to an open message, so existing automated confirmations stay deterministic.

## Reviewing drafts (review mode)

When the program is in review mode, a **"Draft(s) awaiting review"** card appears at the top of the patient's page (above the tabs, so it's never missed) whenever a reply is waiting:

1. Read the drafted reply, along with its detected **intent** and **triage band** badges.
2. Either:
   - Click **Approve & send** to deliver it exactly as drafted, or
   - Edit the text in place, which changes the button to **Send edited reply**, or
   - Click **Discard** to drop the draft entirely (nothing is sent).

Approving goes through the same delivery path an auto-mode send would — the patient sees exactly what they'd have gotten in auto mode.

## Escalations

An **Escalations** card on the patient's page lists everything the patient agent has flagged: a **Red flag**, an **Agent-flagged triage**, a failed turn (**Agent turn failed**), an **Out of scope hand-off**, or something a staff member flagged manually. Each shows its severity, status, and timestamp.

- Click **Acknowledge** to mark an open escalation as seen.
- Click **Resolve** once it's been handled.

If no one was actively covering the configured escalation role at the time, the card notes that the program owner was notified instead as a fallback — a visible signal that the rota needs attention.

## Preview chat

Before turning the agent loose on real patients (or after editing an already-bound agent), use **Preview chat** from that agent's row on the Agents tab:

1. Pick a real cohort patient to test against — the preview uses their actual program context.
2. Type messages as if you were that patient and see the agent's replies in a sandbox chat window.

**Nothing in a preview is sent to the patient or saved to their message history** — appointment bookings and escalations run in a simulated dry-run mode only. This is the recommended way to walk through appointment, education, red-flag, and out-of-scope scenarios end to end before enabling the binding for real, or before promoting a program from review to auto mode.

## Recommended rollout

Start a new patient agent in **review mode** on a single pilot program, with staff approving every reply for a defined window. Only switch to **auto** mode after you've reviewed the draft/edit rate and are comfortable with what it's producing.
