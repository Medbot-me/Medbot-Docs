# Patients & Cohort

## The shared patient directory

Patients live in one **shared, platform-wide directory** (`/patients`) — not owned by any single program. The same patient can sit in more than one program's cohort at once.

To add a brand-new patient to the directory, click **Add patient** from `/patients` and fill in: first name, last name, phone number, address, age, and gender. No Clerk account is required for a patient. From here you can also **Edit** or **Delete** a patient — deleting removes them from the directory and every program's cohort, and cannot be undone.

## Adding a patient to a program's cohort

From a program's **Patients** tab (or the setup wizard's Patients step, or `/programs/[programId]/board`), click **Add patient to cohort**:

1. Select a patient from the shared directory (only patients not already in this program's cohort are offered — if the list is empty, everyone in the directory is already in this cohort; add a new patient from the directory first).
2. Optionally add **Clinical notes** — referral letters, consult notes, discharge summaries, etc. This is saved as the patient's **first encounter note** for this program, and their AI **agent context** is generated from it automatically.
3. Click **Add to cohort**.

If the program has **on patient added** settings configured (see [Creating a Program](/docs/care-programs/getting-started#step-6--settings)), adding a patient can also trigger a welcome message and/or a program agent run against just that patient — you'll see a toast confirming what happened (message sent, skipped due to opted-out consent, no content configured, etc.).

To remove a patient from a cohort (without deleting them from the directory), use the **X** action on their row and confirm. This only unlinks them from this program — they stay in the shared directory and any other program's cohort.

## The cohort roster

The roster table on a program's Patients tab shows, per patient: **pending tasks, notes, messages, and last message time** — enough to see who needs attention without leaving the page. Click a patient's name (or the eye icon) to open their full page.

## A patient's own page

Each patient has a dedicated page per program (`/programs/[programId]/patients/[patientId]`) bringing together everything about them in that program:

- **Header** — name, gender, phone, age, address.
- **Agent context** — an AI-maintained briefing card (markdown), kept current automatically as encounter notes are added; can also be hand-edited or regenerated directly.
- **Draft awaiting review** — if the patient agent is in review mode and has a drafted reply waiting, it's shown here regardless of which tab is active (see [Patient Agent](/docs/care-programs/patient-agent)).
- **Escalations** — any open/acknowledged/resolved escalations raised by the patient agent.
- **Encounter notes** tab — the full note history in a sidebar, with an editor for the selected note (or a fresh one).
- **Message history** tab — the SMS/WhatsApp thread with this patient, plus a box to send a message directly.
- **Appointments** tab — upcoming and past bookings, plus a manual "Book for this patient" flow (see [Appointments](/docs/care-programs/appointments)).

### Encounter notes

Encounter notes are the patient's running clinical record within this program — referral letters, consult notes, discharge summaries, follow-up notes, preferences, allergies, etc. Every save automatically **folds the note into the agent context** above it — there's no separate "regenerate context" step to remember. Notes can be deleted individually (this doesn't retroactively rebuild the context from what remains).

### Sending a message

The message box under Message history lets a staff member send a **free-text SMS or WhatsApp** message to the patient immediately via Twilio. The thread badges each message by who/what sent it: **Staff** (manual send), **Agent** (the patient agent), **Emergency escalation** (the agent's fixed red-flag message), or an unbadged bubble for an automated journey send.
