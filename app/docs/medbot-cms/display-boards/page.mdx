# Patient-Facing Displays

The unauthenticated `/display/{token}` route is built for wall-mounted lobby and room-door screens. It renders with no staff navigation or Clerk UI, and polls `/api/queue?token=...` every four seconds while visible.

## Creating a display

Admins manage display devices from the **Displays** panel on [Session Setup](/docs/medbot-cms/session-setup). A display is scoped to one clinic location and is either a **waiting-room board** or a **room-door screen** — room-door displays must be assigned to one active room.

Creating a display issues its `/display/{token}` URL exactly once; only a SHA-256 hash of the token is stored server-side, so a lost URL can't be recovered — revoke it and create a new device instead.

## What each board shows

`/api/queue` supports two read paths:

- **Signed-in staff** with `admin`, `receptionist`, `doctor`, or `nurse` receive the full queue projection used by staff screens, optionally scoped with `?locationId=...`.
- **Display-device tokens** receive a PHI-free public board for that device's own location only.

Waiting-room boards show the latest called ticket for each room plus checked-in, not-yet-called tickets. Room-door boards show only the current ticket called to that device's room. Neither ever shows a patient identifier — device tokens are bearer credentials, so treat the URL itself as something to keep private.
